Scalability — Summaries Subcollection
  • Add users/{uid}/summaries/{yyyy-mm} storing pre-computed monthly totals (income, expenses, savings, per-category). Updated atomically with every transaction write via FieldValue.increment in a batched write.
  • Dashboard reads a single document instead of aggregating all transactions client-side — reduces Firestore reads from O(n) to O(1) per page load.
  • Budget page uses the same summary doc for instant category totals without scanning every transaction for the month.

interface Instrument {
  id: string;  userId: string

async function addTransaction(data: TransactionInput) {
  const temp = { ...data, id: crypto.randomUUID(), createdAt: Date.now() }
  await mutate('/api/transactions',
    (current) => [temp, ...current],
    { revalidate: false }  // update UI instantly, no spinner
  )
  await fetch('/api/transactions', { method: 'POST', body: JSON.stringify(data) })
  mutate('/api/transactions')  // revalidate to get server-assigned ID
}

Firestore Atomic Batch Writes

// Never write transaction + summary separately — use a batch
async function addTransactionWithSummary(tx: Transaction) {
  const batch = db.batch()

  const txRef = db.collection(`users/${uid}/transactions`).doc()
  batch.set(txRef, { ...tx, createdAt: serverTimestamp() })

  const summaryRef = db.doc(`users/${uid}/summaries/${tx.salaryMonth}`)
  batch.set(summaryRef, {
    expenses: FieldValue.increment(tx.type === 'expense' ? tx.amount : 0),
    income:   FieldValue.increment(tx.type === 'income'  ? tx.amount : 0),
    [tx.category]: FieldValue.increment(tx.amount)
  }, { merge: true })

  await batch.commit()  // atomic — both succeed or both fail
}
Composite Firestore Indexes (firestore.indexes.json)
  • Transactions page: [userId, createdAt DESC] and [userId, type, createdAt DESC] for type-filtered views
  • Budget queries: [userId, fiscalYear, category] — enables FY category roll-up without client-side scan
  • Schedules cron: [userId, status, nextRunAt ASC] — finds all active due schedules efficiently
  • Instruments portfolio: [userId, status, type] — fast active-by-type filtering
  • Deploy all with: firebase deploy --only firestore:indexes

Firestore Security Rules

// firestore.rules — deploy before launch
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // System lookup tables: authenticated reads only, no writes
    match /platforms/{doc} { allow read: if request.auth != null; }
    match /providers/{doc} { allow read: if request.auth != null; }
    match /instrument_masters/{doc} { allow read: if request.auth != null; }

    // User data: strictly owner-only access
    match /users/{userId}/{document=**} {
      allow read, write: if request.auth.uid == userId;
    }
  }
}
PWA & Offline Strategy
  • Enable Firestore enablePersistence() — offline reads from local cache while reconnecting.
  • Add PWA manifest + service worker (next-pwa or manual) — cache static assets and last-loaded page data.

  • Verify X-Telegram-Bot-Api-Secret-Token header on every webhook request — set during webhook registration, reject without it.

Schedule Logic (No RRule)

// utils/schedule.ts — simple, no library
function getNextRunAt(s: Schedule): number {
  const now = new Date()
  if (s.frequency === 'monthly') {
    const next = new Date(now.getFullYear(), now.getMonth(), s.dayOfMonth)
    if (next <= now) next.setMonth(next.getMonth() + 1)
    return next.getTime()
  }
  // similar branches for weekly, quarterly, yearly
}

function scheduleLabel(s: Schedule): string {
  if (s.frequency === 'monthly')   return `Monthly on the ${ordinal(s.dayOfMonth)}`
  if (s.frequency === 'weekly')    return `Every ${dayName(s.dayOfWeek)}`
  if (s.frequency === 'quarterly') return `Quarterly on the ${ordinal(s.dayOfMonth)}`
  if (s.frequency === 'yearly')    return `Annually on ${formatDate(s.dayOfMonth, s.month)}`
  return s.frequency
}
// → "Monthly on the 5th"
// → "Every Monday"
// → "Quarterly on the 1st"
